Marketing website for Onyxx Tech (AI agents/chatbots/custom software studio), a static no-build HTML/CSS/JS site deployed on Vercel, repo `onyxtech26/Onyxx-Tech`.

## Session continuity & documentation
**At session start:** read `PROJECT_STATUS.md` in this folder first to restore where we left off, what's done, and what's next. Treat it as the source of truth for project state.

**Document big tasks without being asked.** When a milestone/feature/decision/multi-step task completes:
- Append a dated entry to `docs/CHANGELOG.md` (what was done, why, key decisions).
- Move the item to ✅ Done in `PROJECT_STATUS.md` and add a Session-log line.
A "big task" = something worth remembering in a month; skip routine edits and intermediate steps.

**When starting new work** add it under 🔄 In progress in `PROJECT_STATUS.md`. **When wrapping up**, refresh 📍 Where I left off and bump Last updated. Keep edits surgical.

## Project-specific notes for future sessions
- **Redesigned 2026-10-29, dark brand version chosen by the owner.** Near-black base, off-white text, the Onyxx cyan (`--accent`) used sparingly, Archivo + Inter, positioned around **website design in Johor Bahru**. The brand motif is the logo's circuit traces (`images/trace.svg` above section headings, `images/circuit-x.svg` behind the CTA, ring-node list bullets). The original galaxy lives on in the homepage hero only (`.hero-sky` canvas, `initHeroSky()` in `site.js`, core at 78%/32%, paused off screen, still for reduced motion). The old splash, `styles.css` and `common.js` are gone.
- **No build tool, on purpose.** Plain `<link>`/`<script src>`. Every public page links `/site.css` and `/site.js` (deferred, an IIFE). The page shell (`<head>`, header, footer) is duplicated in each HTML file; it was produced once by a throwaway generator, so a shell change means editing every page (or regenerating). Keep shared things in `site.css` / `site.js`.
- **Every word on a public page is in the HTML.** Nothing is loaded from Supabase for display any more (the admin "Project Showcase" tab no longer drives `/work`). `site.js` only adds the mobile menu, reveals, WhatsApp button, analytics and the contact form. Pages must read fully with JS off.
- **Pages:** `/` (home), `/website-design` (main SEO page), `/services`, `/custom-software`, `/chatbots`, `/ai-agents`, `/automations`, `/work`, `/case-studies/*` (9), `/blog`, `/blog/*` (4), `/contact`, `/privacy`, `/cookies`, plus a `404.html` (noindex). Clean URLs via `vercel.json`, so links are root-absolute and extensionless (`href="/work"`). `/web-apps`, `/founders`, `/why`, `/process` 301 to their replacements.
- **The contact form** posts straight to PostgREST (`/rest/v1/contact_messages`, anon key, `Prefer: return=minimal`) from `site.js`; RLS allows anon INSERT only. Tests must intercept `*.supabase.co`.
- **Run `python tools/stamp_assets.py` after editing `site.css`, `site.js` or the admin pair**, before committing: Cloudflare caches static assets for 4 hours.
- **Copy style for the public site:** no em dashes (use commas, colons, full stops or brackets), plain descriptive headings rather than slogans, no filler words like "honestly", "actually", "genuinely", and no small label above every heading. The owner asked for this explicitly to avoid an AI-written look.
